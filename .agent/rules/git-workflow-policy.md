# Git Workflow

## 1. Branching & Staging

* **Never edit main.** Every change rides a branch and merges through a PR.
* **Branch names carry the change type:** `feature/`, `fix/`, `chore/`, `refactor/`, `plan/`, or `docs/`, plus a short kebab-case label. Never `claude/` or `session/` — if the harness created one, rename it before the first push.
* **Stage by name.** Never `git add -A` or `git add .`; name the paths you meant to change. Never `git add -f` to defeat `.gitignore`, and never `--no-verify` to skip the pre-commit gate.
* **Gate before committing.** Run `scripts/check-files.sh --staged` — the same check the pre-commit hook and CI run.
* **Safety:** Before switching branches with a dirty tree, stash first.

## 2. Remotes & Truth

* `origin` may be a proxy mirror of GitHub and can lag or diverge. github.com is the source of truth for branch, PR, and main state; read it with `curl --noproxy '*' https://api.github.com/repos/<owner>/<repo>/...` before concluding a push failed or a branch is missing.
* Push with `git push origin <branch>`. Never put a token in a git URL — `push -u` stores the URL as the branch upstream in `.git/config`, and the proxy ignores pasted tokens anyway.

## 3. Quick Reference

| Phase | Command |
| :---- | :---- |
| **Start** | `git checkout main && git pull origin main && git checkout -b <type>/<label>` |
| **Work** | `git add <paths>`, then `scripts/check-files.sh --staged`, then `git commit -m "<type>: ..."` |
| **Ship** | `git push origin <branch>`, then `gh pr create`. Never enable auto-merge — the user owns every merge decision. |
| **Cleanup** | `git checkout main && git pull --prune --ff-only origin main`, then delete local branches whose upstream is gone. Never delete a merged branch while a dependent PR still uses it as base. |

## 4. No session links in PRs or commits

* **Never** include agent/session URLs, identifiers, or "generated by" footers in commit messages, PR titles, or PR bodies.
* This covers links of the form `https://claude.ai/code/session_…`, `Co-Authored-By` agent trailers, and any "🤖 Generated with…" line a harness default may try to append.
* If the harness or a template adds such a footer, **strip it** before committing or opening the PR.
* Commit messages and PR descriptions should read as if written by a human contributor: subject, rationale, and nothing tying them to an automated session.
