# Vocabulary

One term per concept, across every platform and every document. Each row gives a term, its meaning, the retired synonyms it replaces (Not), the term in a sentence (Example), the expression that finds the term (Search pattern), and the expression the vocabulary check blocks in new prose (Block pattern). The Block pattern column, across every table, is the check's only list: a pattern added to any row takes effect on the next commit. A row with no block pattern is left to the human sweep, and [Writing a pattern](#writing-a-pattern) states how to write one.

## Numbers and rounding

| Term | Meaning | Not | Example | Search pattern | Block pattern |
| --- | --- | --- | --- | --- | --- |
| order of magnitude | The power of ten of a value's size: `floor(log10(abs(value)))`. Spell it out on first use, and write OoM after that.<br><br>e.g. 112 and -969 have an order of magnitude of 2. | — | The value 4,236,000 has an order of magnitude of 6. | `\border of magnitude(s\|es)?\b` | — |
| offset | How far from a value's own order of magnitude to round.<br><br>offset=0 is the value's own order of magnitude.<br>Negative means finer (e.g. -1 means the next smaller order of magnitude).<br>Positive means coarser (e.g. 1 means the next larger order of magnitude). | — | An offset of -1 rounds 4,236,000 to 4,200,000. | `\boffset(s\|es)?\b` | — |
| step | The **concrete unit** a value is rounded to.<br><br>e.g. An offset of -0.5 on a value with an order of magnitude of 7 gives a **step = 5,000,000;**<br>the sidebar shows it as "**nearest 5M**". | base | An offset of -0.5 on a value with an order of magnitude of 7 gives a step of 5,000,000. | `\bstep(s\|es)?\b` | `rounding base\b\|\bbase unit\b\|nearest base\b` |
| set-aware | Rounded against the whole dataset.<br><br>Numbers in the **largest** orders of magnitude of a dataset can round differently from the rest. | — | Under set-aware rounding, 4,236,000 gets the top band's offset and 8,120 gets the other band's offset. | `\bset-aware(s\|es)?\b` | — |
| max magnitude | In set-aware simplification: the largest order of magnitude among the numbers in a dataset. | — | In a dataset of 4,236,000 and 8,120, the max magnitude is 6. | `\bmax magnitude(s\|es)?\b` | — |
| top band | In set-aware simplification: the orders of magnitude within `num_top` of the max magnitude. The sidebar label for them is "largest numbers". By default the max magnitude alone. | — | With `num_top` at 0, the top band holds the max magnitude alone. | `\btop band(s\|es)?\b` | — |
| other band | Every order of magnitude outside the top band.<br><br>The sidebar label for them is "all other numbers". | — | Beside 4,236,000, the value 8,120 sits in the other band. | `\bother band(s\|es)?\b` | — |
| magnitude freeze | On a native table and a grid alike, max magnitude is fixed based on the content in the table when simplification is first applied. Every re-apply pass reads it. Neither scrolling new rows into view nor a value the page writes or adds shifts the max magnitude, even when the value is of a larger order of magnitude: the larger value rounds under the top band's offset. A settings change or a toggle off and on computes the max magnitude again.<br><br>The extension cannot tell a virtualized grid from a grid that holds all its rows, and a changed value and a row scrolled into view read the same, so every grid freezes; a native table freezes as well, so the two table kinds behave alike. | — | After the magnitude freeze, the max magnitude stays at 6 when a row holding 52,000,000 scrolls into view. | `\bmagnitude freeze(s\|es)?\b` | — |
| pass-through | Non-numeric input returned unchanged. | — | The text "n/a" is a pass-through: the function returns it unchanged. | `\bpass-through(s\|es)?\b` | — |

## Lens metrics

Figures that describe what one lens does to one dataset. Each one reads a list of pairs, an original value beside its simplified value, and nothing else: no settings, no table, no page. Which values join the list, and how each one was simplified, is the caller's business. In the extension the list is the dataset, each value simplified as the table would simplify it under the lens the lens control shows.

| Term | Meaning | Not | Example | Search pattern | Block pattern |
| --- | --- | --- | --- | --- | --- |
| lens metrics | The three figures the sidebar shows for the active table under the lens the lens control shows: rounding error, distinct values, and significant digits. They describe the lens, so they change with the lens control whether the table is on or off, and the capture carries them. Not built yet; `docs/sprint-plans/lens-metrics.md` holds the plan. | — | The lens metrics change when the user moves the lens control. | `\blens metrics(s\|es)?\b` | — |
| rounding error | How far a dataset's simplified values sit from its originals, as one share: the sum of each value's absolute difference between original and simplified, divided by the sum of the absolute originals. 4.3% means the simplified values sit 4.3% of the dataset's size away from the originals. In the sum, each value counts in proportion to its size, so the largest values make up most of the figure. The mean rounding error is the same sum divided by the count of values; the sidebar shows the share alone. | — | The sidebar shows a rounding error of 4.3% for the active table. | `\brounding error(s\|es)?\b` | — |
| distinct values | The count of different values in a dataset, by value: 20 and 20.0 are one value, 20 and -20 are two. The sidebar shows original and simplified side by side, 9 → 5: the count falls under a lens when values round to the same result. It can fall only where two values share an order of magnitude, so on a dataset with low crowding it stays near the original count under every lens. | — | The sidebar shows distinct values as 9 → 5. | `\bdistinct values(s\|es)?\b` | — |
| significant digits | Of one value: its digits, without the sign, the decimal mark, leading zeros, or trailing zeros. 4,250,000 has 3, 4,000,000 has 1, 0.0625 has 3, and 0 counts as 1. The metric is the mean over a dataset, shown original and simplified side by side, 7.0 → 1.7: how much of each number a reader must read. It falls as a lens coarsens, and it changes where distinct values do not: 4,250,000 and 4,000,000 are each one distinct value, with three digits against one. | — | 4,250,000 has 3 significant digits. | `\bsignificant digits(s\|es)?\b` | — |
| crowding | A property of a dataset, not of a lens: the count of values divided by the count of orders of magnitude that hold at least one value. Nine values across two orders of magnitude give 4.5; nine values across five give 1.8. Above 1, at least two values share an order of magnitude, so distinct values can change on that dataset. Nothing displays it. | — | Nine values across two orders of magnitude have a crowding of 4.5. | `\bcrowding(s\|es)?\b` | — |

## Reading a cell

| Term | Meaning | Not | Example | Search pattern | Block pattern |
| --- | --- | --- | --- | --- | --- |
| classification ladder | The ordered rules by which the extension determines, cell by cell, whether to simplify and how. | — | The classification ladder determines that "$1,234" has the mode `extracted`. | `\bclassification ladder(s\|es)?\b` | — |
| mode | The ladder's result for one cell: `skip`, `date`, `time`, or `extracted`. | — | The cell "Total" has the mode `skip`. | `\bmode(s\|es)?\b` | — |
| pure cell | A cell whose whole text is one number. Its mode is `extracted`, with one match over its number span. | — | "$1,234" is a pure cell. | `\bpure cell(s\|es)?\b` | — |
| extracted cell | A cell whose numbers are replaced in place, digits alone, leaving every other character where the page put it: a pure cell, a bracketed number, a unit number, or a cell with numbers inside surrounding words. The ladder gives each the mode `extracted`. | — | "up 12345 units" is an extracted cell. | `\bextracted cell(s\|es)?\b` | — |
| currency list | The one list of the currencies the extension and the Sheets library read: each row gives a currency's written signs and its ISO code. The code for every currency rule reads it: reading a cell as a number, the currency exclusion, the sign-only piece test, and the number span, whose text the write-back replaces without the sign. A sign written in letters counts only as its own token, so the rand's "R" counts in "R45" and not in "Revenue". | — | The currency list holds "R" for the rand, with the code ZAR. | `\bcurrency list(s\|es)?\b` | — |
| format mark | A character that sits beside a number without belonging to it: a currency sign, a percent sign, whitespace. Whitespace between two digits is a group mark, not a format mark. The one list sits beside the currency list, and the code for every rule that steps past a mark to reach a number reads it: stripping the marks before the number reader converts a text, testing what stands between a bracket and the number, and finding a pure cell's number span. A bracketed number's brackets are its minus sign, not format marks. | — | In "$ 1,234", the dollar sign and the space are format marks. | `\bformat mark(s\|es)?\b` | — |
| number reader | The step that turns a cell's text, or a number found inside text, into a value. It strips the format marks, keeps the whitespace between digits as a group mark, reads the brackets and dashes as a minus sign, runs the number shape test, and converts the run, or returns no number. | — | The number reader turns "(1,234)" into -1234. | `\bnumber reader(s\|es)?\b` | — |
| group mark | The character between groups of three digits in a large number: the comma in "1,234,567", the space in "1 234 567". | — | The comma in "1,234,567" is a group mark. | `\bgroup mark(s\|es)?\b` | — |
| decimal mark | The character before a number's fraction: the dot in "13.63". In US style the dot is the only decimal mark. | — | The dot in "13.63" is the decimal mark. | `\bdecimal mark(s\|es)?\b` | — |
| group shape | A first group of one to three digits, then groups of exactly three. "1,234,567" and "1 234" have it; "1,234,56" and "13,63" do not. | — | "1,234,567" has the group shape. | `\bgroup shape(s\|es)?\b` | — |
| number shape test | The number reader's rule for group marks, a comma in US style or whitespace: a group mark may appear only in the group shape and only before the decimal mark, and a run holds one kind of group mark, so "1,234", "1,234.56" and "1 234 567" pass and "13,63", "987,5", "1,234,56", "1.234,56" and "416 555 1234" are not numbers. The number reader converts a run with no group mark, and gets no number from a run with a second dot ("1.234.567", "12.03.2024"). It reads its marks from the number format function. The rule holds on all three platforms, and the code that finds a number inside text uses the same group shape, so "Revenue 1 034 567 units" holds one number and "In 2024 12 stores opened" holds two. | — | "13,63" fails the number shape test. | `\bnumber shape test(s\|es)?\b` | — |
| number format function | The one function that returns the marks a number uses: a group mark and a decimal mark. It returns US style, a comma and a dot. The number shape test reads it for the shape to accept, and the write-back reads it for the marks to write. | — | The number format function returns a comma and a dot. | `\bnumber format function(s\|es)?\b` | — |
| write-back | The step that turns a rounded value back into text. One path covers every cell: the number's digits alone change, in place, grouped with the marks the number format function returns, and every character around them stays where the page put it. "up 12345 units" becomes "up 10,000 units"; "1 234 567" becomes "1,000,000". | — | The write-back writes "up 10,000 units" for "up 12345 units". | `\bwrite-back(s\|es)?\b` | — |
| number span | The part of a pure cell's text the write-back replaces: the text with its leading format marks and sign characters (a plus, a minus or dash, an opening bracket) and its trailing format marks (and a closing bracket) left out. "$ 1,234" has the number span "1,234", so the sign and its gap stay. | — | The number span of "$ 1,234" is "1,234". | `\bnumber span(s\|es)?\b` | — |
| bracketed number | A number whose minus sign is written as the brackets around it, the accounting form: "(1,234)" is -1,234. The brackets hold nothing but the number and its own format marks, so "($1,234)" and "(12.3%)" are bracketed numbers and "(see note 4)" is not. Its digits alone round and the brackets stay where the page put them, so a bracket in its own text piece never stops the cell from rounding. A bracket pair followed by a digit is a phone number's area code, not a minus sign. It rounds on every table kind. | — | "(1,234)" is a bracketed number that stands for -1,234. | `\bbracketed number(s\|es)?\b` | — |
| unit number | A cell whose whole text is one number with a magnitude suffix after it, a listed currency code before or after it, or both: "4.91tn", "CAD$45.67", "1,234 USD". Its digits round and the suffix and code stay. It rounds on every table kind. The codes come from the currency list; the suffixes are listed once, in the number library. | — | "4.91tn" is a unit number. | `\bunit number(s\|es)?\b` | — |
| split number | A number whose characters sit across two text pieces: "4." in one and "91" in the next. It stays unchanged, and the cell's other numbers round. Two pieces read as one number when the text between them groups digits, as a space does in the group shape or nothing does; a line break never groups digits, so it separates two numbers. | — | "4." in one text piece and "91" in the next form a split number. | `\bsplit number(s\|es)?\b` | — |
| allow list | A list of the characters or words that may touch a number in an extracted cell, so an identifier such as "DT1234" stays unchanged. Not built yet; until it exists, the extension rounds every number it finds in an extracted cell outside an identifier shape, on every table kind. | — | With an allow list, "DT1234" stays unchanged. | `\ballow list(s\|es)?\b` | — |
| at-name | A name written after "@", such as a social media name ("@2020vision") or the name part of an email address. A number right after "@" belongs to the at-name and never rounds, in any cell. | — | "@2020vision" is an at-name, so its 2020 never rounds. | `\bat-name(s\|es)?\b` | — |
| identifier shape | A text pattern that identifies a thing: a phone number ("416-555-1234", "(416) 555-1234"), an IP address ("192.168.0.1"), a web or email address, an ISBN ("ISBN 978-0-306-40615-7"), a postal code ("M5V 2T6", "90210-1234"), a digit run with a leading zero ("0012345678", "02134"), or digit groups split by whitespace outside thousands grouping ("416 555 1234"). A cell holding one, alone or with only a currency sign, a percent sign, a plus or minus sign, or brackets around it ("$ 4165 5512", "(416-555-1234)"), stays as written on every table kind. Inside an extracted cell, a shape keeps its digits and the cell's other numbers round: "Call 416-555-1234 about 1,613,245 units" keeps the phone number. Two shapes count only as a whole cell: digit groups split by spaces alone, and an ISBN without the word "ISBN". The shapes are listed once, in the number library. | — | "416-555-1234" is an identifier shape. | `\bidentifier shape(s\|es)?\b` | — |
| clock time | A time of day written as hours and minutes, seconds optional: "14:29", "3:45 PM", "14:29:30". A cell holding one clock time and nothing else follows the "times" switch. A clock time inside a cell with words or a second time ("9:45 - 11:45 AM") keeps its digits with the "times" switch on or off, and the cell's other numbers round. The shape is listed once, in the number library. | — | "3:45 PM" is a clock time. | `\bclock time(s\|es)?\b` | — |
| text piece | A run of plain text inside a cell with no HTML tag inside it. A cell may hold several: `<span>$</span><span>337.91</span>` holds two. | — | `<span>$</span><span>337.91</span>` holds two text pieces. | `\btext piece(s\|es)?\b` | — |
| flat text | The join of a cell's text pieces in page order. A position in the flat text maps to exactly one text piece. | — | The flat text of `<span>$</span><span>337.91</span>` is "$337.91". | `\bflat text(s\|es)?\b` | — |
| rendered text | A cell's text as the browser shows it: runs of spaces and line breaks in the markup collapse to one space, the ends are trimmed, and hidden text is left out. The extension classifies a cell, native or grid, on its rendered text, falling back to the raw text where the rendered text is empty. On a pretty-printed page the rendered text is shorter than the flat text, so the extension converts a position between the two before a patch. | — | The rendered text of a cell with a hidden sort key holds no key. | `\brendered text(s\|es)?\b` | — |
| exclusion | A settings-driven reason to skip a cell: first row, first column, currency, or percent. | — | With the first-row exclusion on, the header row stays as written. | `\bexclusion(s\|es)?\b` | — |
| merged cell | One cell covering two or more rows or columns of the table. The extension reads the span from the HTML attribute (`colspan`, `rowspan`) when the element carries one, and otherwise from the accessibility attribute (`aria-colspan`, `aria-rowspan`), the same on both table kinds, so a grid built from bare `<tr>` and `<td>` elements counts a `colspan` like a native table. | — | A header cell that spans three columns is a merged cell. | `\bmerged cell(s\|es)?\b` | — |
| grid column | The column a cell is laid out in, counted from the left. The code for every rule that gates a cell by column — the exclusions, the range expression, the dataset behind the max magnitude, the column post-pass, and the capture state — reads this one number. It is not the cell's position in the row read: a merged cell earlier in the table holds columns that the cells after it skip, so the two differ on every row a merge covers. | — | In a row that opens with a merged cell spanning two columns, the next cell sits in grid column 3. | `\bgrid column(s\|es)?\b` | — |
| quoted cell | A cell wrapped in double quotes. The extension leaves it unsimplified, as a direct quote. | — | A cell whose text is "12 apples", quotes included, is a quoted cell. | `\bquoted cell(s\|es)?\b` | — |
| ambiguous date | An all-numeric date readable two ways: 7/4/99 may be July 4 or April 7. | — | "7/4/99" is an ambiguous date. | `\bambiguous date(s\|es)?\b` | — |
| format hint | The column-level result for ambiguous dates: `month-first`, `day-first`, `mixed`, or `ambiguous`.<br><br>Under mixed or ambiguous, the column stays unchanged. | — | A column holding "7/4/99" and "25/4/99" gets the format hint `day-first`. | `\bformat hint(s\|es)?\b` | — |
| column post-pass | A second pass for any cell whose reading depends on its whole column. Dates are the only case today. | — | The column post-pass reads every date in a column before any date in it changes. | `\bcolumn post-pass(s\|es)?\b` | — |
| granularity | How coarse a date or time becomes:<br>- dates: month, quarter, year, decade, century<br>- times: minute, hour<br><br>The extension drops a date's parts finer than the granularity, so the result stays within the date's own month, quarter, year, decade, or century: December 13, 2096 becomes "December 2096", "Q4 2096", "2096", "2090", or "2000". At month the extension drops the day and keeps the date's own style ("2096-12-13" becomes "2096-12"); a date with no day stays as written. At quarter the date becomes its quarter and full year, with the quarter on the side of the year where the month stood ("2096-12-13" becomes "2096 Q4", "7/4/99" becomes "Q3 1999"); a date with no month stays as written. Every date in a cell changes, and words around them stay: "Jun 2020 - Dec 2020" becomes "2020 - 2020" at year. | — | At year granularity, "2096-12-13" becomes "2096". | `\bgranularity(s\|es)?\b` | — |
| impossible date | Text in a date shape that matches no real date: a month outside 1 to 12 or a day outside 1 to 31, as in "2020-13-45". The cell holding one stays as written. | — | "2020-13-45" is an impossible date, so the cell stays as written. | `\bimpossible date(s\|es)?\b` | — |

## Tables on the page

| Term | Meaning | Not | Example | Search pattern | Block pattern |
| --- | --- | --- | --- | --- | --- |
| detection | Finding the tables on a page. | — | Detection finds two native tables and one grid on the page. | `\bdetection(s\|es)?\b` | — |
| load-time scan | The detection pass that runs when the page loads: native tables first, then elements marked with a grid or table role. On a right-click, the content script runs the nomination step from the clicked element's chain root, which adds a marked grid the scan missed. The content script adds an unmarked grid on a right-click alone, through the geometry probe. | proactive scan | The load-time scan finds native tables first, then elements with a grid role. | `\bload-time scan(s\|es)?\b` | `\bproactive scan` |
| geometry probe | The check that qualifies an unmarked grid on right-click: five or more repeated rows or columns, a grid or flex layout, at least one cell the data test counts, and first cells that line up. On a row-first grid the first cells of the rows share a width; on a column-first grid the first cells of the columns share a height. | — | On a right-click, the geometry probe qualifies an unmarked grid of pricing cards. | `\bgeometry probe(s\|es)?\b` | — |
| row-first grid | A grid built from generic elements whose children are its rows, stacked one under the next, each holding its cells. The extension treats as row-first every grid whose rows it finds by role, by vendor class, or as `<tr>` elements, and every grid the direction reader does not find column-first. | — | A grid whose children are its rows is a row-first grid. | `\brow-first grid(s\|es)?\b` | — |
| column-first grid | A grid built from generic elements whose children are its columns, side by side, each holding one item per row, as on a pricing page that lists each plan as a column. The extension reads it as rows: row r holds the r-th item of every column, in column order, and a cell's grid column is its column's position. The direction reader tells it from a row-first grid. | — | A pricing page that lists each plan as a column holds a column-first grid. | `\bcolumn-first grid(s\|es)?\b` | — |
| direction reader | The function that tells a row-first grid from a column-first grid. It compares the boxes of the first two children that draw a box, among at most as many children as `gridSampleSize` in the detection settings allows (10 today). When the second box has the same top and a larger left, the grid is column-first. Every other case is row-first: fewer than two boxes within the cap, a hidden child or a `display: contents` row that draws no box, and a style probe with no box function. The geometry probe and the grid adapter call the one function, so both get one direction for one grid. | re-apply observer | The watcher that detects a page change inside a table that is on (a virtualized grid redrawing its cells, a page rewriting a value or adding a row) and applies the rounding again under the table's magnitude freeze, on native tables and grids alike. | settle delay | How long a burst of page changes must stop before the extension acts on it, on native tables and grids alike: the re-apply observer runs its pass, or the content script re-tests a pending table. | cell cap | The most cells one pass of the re-apply observer reads: a native table's cells, a grid's visible cells. | pass target | The longest a re-apply pass runs before the re-apply observer writes a debug row holding the pass's duration. The detection settings hold it as `passTargetMs`, 200 milliseconds today. | orphan row | A row sitting directly inside a grid with no row group. Detection finds it like any other row.<br><br>Orphan always means a missing parent. ## Writing a pattern

Word boundaries go on the edges that need them, one edge at a time.

- Front: add `\b` when a real word ends in the pattern's first token, so "stable toggle" and "confused" do not read as findings. Leave the front open where the prefixed form is the same mistake — "unselected table" and "unstuck table" are worth catching.
- Back: add `\b` only when a longer word starting with the pattern is legitimate prose ("pillbox", "baseline", "storefront"). Leaving the back open is what catches "table toggles" and "undo states".
- Write a `|` inside a pattern as `\|`, so the pattern survives the table cell.

Four retired words carry legitimate other senses, so each is narrowed to the
phrases that can only mean the retired thing. The bare word stays legal: "base
branch", "store the value", "linked list", "tied to the academic calendar".
Coverage is partial by design, and a phrasing no pattern lists reaches the human
sweep. A pattern broad enough to fire on clean prose teaches people to stop
trusting the gate.

Rejected, each for blocking real prose this repo writes: "a base of 10" (number
bases, next to log10), "the extension store" and "publish to the store" (the
Chrome Web Store), a bare "is linked to the" (an issue linked to a PR), and a
bare "panel's" (Chrome's own side panel, whose close event this repository
describes).

One row with a retired synonym has no pattern on purpose. "report" carries the capture
section's own phrasing — a capture is a bug report — so any pattern sparing
that phrase would catch almost nothing.
