DynamicRounding table test page

One fixture per kind of table the Chrome extension handles, plus the kinds it must refuse. Load the unpacked extension, allow file URL access (or serve this page over localhost), and check each section against its stated expectation. Details sit in HTML comments next to each fixture.

Shipped defaults: first row and first column excluded, mixed cells on, currency and percent on, dates on at year granularity, times off. A pillbox is the small on/off control at a table's top-right corner.

23. Cells the page rewrites

Expect: a pillbox at load on 23a's two tables, 23c's grid, and 23d's table. Each table here changes its own values after the extension simplifies it, the way a live dashboard or a scrolling grid does. The extension watches every simplified table, native or grid, and simplifies each change within a moment. A restore always shows the numbers the page last wrote. Reload the page to start any part again. Before this rule, the extension never simplified a native table again after its first simplification, a grid left a changed cell raw, and a restore on either kind wrote the old numbers back over the page's new ones.

23a, one native table and one grid holding the same values. First pull the sidebar's two offsets apart: largest numbers at -1, all other numbers at 0. Add a row with a larger value shows its effect only then, because at equal offsets every value rounds the same whatever the largest value is. Press both pillboxes on, then each button below; every button rewrites the same cell in both tables, so the two results sit side by side. Check each result, then press the pillbox off and check the restore.

  • Write a new number writes 953,877 into South, Q2. Expect: the cell shows 953,877 simplified, and the native cell's hover text shows 953,877. Restore shows 953,877. Before: the cell stayed raw, and the restore wrote 947,310 back.
  • Write a round number writes 400,000 into East, Q1. Expect: the cell shows 400,000 and is no longer simplified: no hover text, and restore leaves 400,000. Before: the restore wrote 427,808 back.
  • Write a word writes n/a into Central, Q3. Expect: the cell shows n/a with no hover text, and restore leaves n/a. Before: the restore wrote 93,662 back.
  • Rewrite one piece writes 15,118 into the italic part of West, Q3. Expect: both numbers in the cell show simplified, the bold one from 281,745 and the italic one from 15,118. Restore shows 281,745 and 15,118. Before: the bold number stayed simplified, the italic number stayed raw, and the restore wrote 12,406 back.
  • Redraw the original writes the cell's own original, 1,482,391, back into North, Q1, as a page redraw does. Expect: the cell shows simplified again within a moment. Before: the grid simplified it again, and the native table left it raw.
  • Add a row with a larger value adds a Global row of values above 12,000,000. Expect: the new row shows simplified on both tables, 12,000,000 and 13,000,000. The native table simplifies every cell again against the new largest value, so the North row, the largest values until now, drops to the coarser rounding (1,500,000 becomes 1,000,000), and its hover text still shows its own originals. The grid keeps the scale it took at its first simplification: its other cells stay as they were, and the Global values take the rounding of the largest values. A grid holds only the rows on the screen, so a larger value the page wrote and a row scrolled into view read the same. Before: the native table left the new row raw.
  • Swap the column set replaces the headers and the first five rows, as a page that loads a different query result into the same table. Expect: the extension detects the table again and simplifies the new values, and the pillbox stays on. The sidebar's active table moves to the new table only when this table was the active one. Before: the new values stayed raw, and the restore wrote the old result set back into the cells.
  • Rewrite as the pillbox is pressed arms the page. The next pillbox press on either table first writes 925,006 into that table's South, Q1, in the same moment as the press, so the restore runs before any pass can read the change. Press it with both tables on. Expect: the restore shows 925,006 in that cell and the originals everywhere else. Before: the restore wrote 918,554 back.

23b, a table that rewrites every value every 30 seconds with a random whole number from 1,000 to 1,000,000. Press its pillbox on. Expect: after each update every cell shows simplified against the new values' largest value, and each hover text shows the new original. A restore at any moment shows the numbers the page last wrote. Before: the cells stayed raw after the first update, and a restore wrote the first round's numbers back.

Next update in 30 seconds.

Store Mon Tue Wed

23c, a scrolling grid that reuses its row elements. The grid holds 60 rows and shows 8; on scroll it keeps the same 8 row elements and writes the next rows' text into them, the way a virtualized grid does. Its Note column alternates between a cell with a bold number (two text pieces) and a plain one (one piece), so each scroll also redraws cells with fewer pieces (issue #423). Press its pillbox on with the offsets from 23a, then scroll down. Expect: every visible cell shows simplified against the scale the grid took at its first simplification; the rows from Account 031 on hold values above that scale, and they take the rounding of the largest values. Scroll back up: the returning rows show simplified again. Scroll down once more and press the pillbox off: the grid shows the values of the rows on the screen, never the numbers of the rows that were there before, and the pillbox turns off. Before: the redrawn cells stayed raw, and a restore wrote the previous rows' numbers into them; a Note cell redrawn with fewer pieces came back with its text doubled, e.g. 1,613 units units.

Account Balance Change Note

23d, the pass measurement and the cell cap. The extension reads at most 10,000 cells in one pass. Build the tables, then press the 1,000-row table's pillbox on and start its updates: they write a value into a random cell every 50 milliseconds, faster than the redraw delay. Expect: each updated value outside the first column shows simplified, one pass a second at most, and each pass writes a debug row in the extension's log with its duration and cell count, under 100 ms. Press the 1,001-row table's pillbox on. Expect: it simplifies with no toast, and a debug row in the extension's log reads that the table holds 10,010 cells, more than the 10,000 the extension follows, so it no longer rounds the page's updates. Press Rewrite a cell: the cell shows 777,777 raw. Press the pillbox off: the cell keeps 777,777, and every other cell shows its original. Before: neither table followed page changes, and the restore wrote the old number back over 777,777.

24. Identifiers

Expect: a pillbox at load on both tables, a native table and a grid holding the same rows. Press each pillbox on. Every Value cell down to US ZIP+4 is an identifier shape and stays as written, on both tables, with no hover text. The Count column rounds as usual. The last three rows round their Value cell: "1 234 567" is thousands grouping and reads as one number, "90210" alone reads as a count, and "Call 416-555-1234" holds words, so its numbers round as any extracted cell does. The sidebar preview samples the Count column and none of the identifiers. Before this rule, every Value cell rounded: "416 555 1234" read as the number 4,165,551,234, "192.168.0.1" rounded its first part, and "M5V 2T6" rounded its 2.
